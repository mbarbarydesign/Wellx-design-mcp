Wellx Unified Design System

The shared visual language for Wellx tools and products. Layout and component patterns come from the first Wellx portal (Flat bordered surfaces, monochrome chrome, one accent); all tokens now come from the Figma "Foundations" library — Wellx brand violet, the Untitled-UI-based color primitives, the Manrope type ramp, and the Radius / Spacing / Semantics collections.

01 — Foundations

Principles

Four rules govern every screen. When in doubt, match an existing pattern — don't invent new ones.

Flat, bordered surfacesPage and cards share one canvas. 1 px hairlines (borders/tertiary) define panels — no shadows, no hover lifts. Shadows survive only in modals, drawers, and auth cards.
Monochrome chromeNav, menus, and hovers use the Gray scale only. The active sidebar item is a gray pill (backgrounds/Active), never a colored one.
One brand accentBrand violet appears only on primary buttons, links, active tab underlines, focus rings, chart lines, and active filter pills. Tenants swap it via parallel Foundations libraries.
Semantic tokens firstComponents consume the Semantics layer (Text / borders / backgrounds / states), which maps to Primitives per Light and Dark mode. Never reach for a primitive directly in UI code.

05B — Iconography

Icons — Lucide

One library everywhere: Lucide (lucide-react). Stroke icons on the 24px grid, rendered at fixed sizes with strokeWidth 1.75. Icons inherit text color — gray in chrome, white inside primary buttons, tone color inside alerts. Never the brand accent in nav or menus.

Sizes by context
16 — buttons, chips, inline
18 — nav, toolbar, topbar
20 — empty states, features

Rules

  • Stroke 1.75 at every size — never mix filled and stroked styles in one surface
  • Color = currentColor; icons never carry their own hex
  • Directional icons (chevrons, arrows, panel toggles) mirror in RTL
  • Icon-only buttons always get aria-label + title
  • In Figma use the Untitled UI icon set — visually equivalent; devs map names to Lucide

Form rules

09B — Motion & RTL

Motion & internationalization

Motion

  • Micro-interactions (hover, fades): 150ms ease-out · layout shifts (sidebar, drawers): 200ms ease-out
  • Dialogs: 200ms fade + scale from 0.98 — no springs, no bounces
  • Animate only transform, opacity, and colors — never width/height of content containers (except the sidebar)
  • Respect prefers-reduced-motion: disable shimmer, pulses, and non-essential transitions
  • Live/urgent dots may pulse (2s) — the only ambient animation allowed

RTL & localization

  • document.dir flips per locale; shared components use logical utilities only (ps-*, border-e, start-*)
  • Arabic uses Alexandria for both display and body; Latin numerals stay tabular
  • Directional icons mirror (chevrons, arrows, panel toggles); charts, media controls, and phone numbers do not
  • Dates localize; IDs and codes (REF-100234) never do
  • Test every new screen in both directions before handoff
10 — Guardrails

Do & don't

Do

  • Consume the Semantics layer (Text / borders / backgrounds / states) — it carries Light/Dark for free
  • Import pills, avatars, and tone maps from the central modules
  • Use the light-tint recipe for chips: 50 background + 700 text + 500 dot (900/300 in dark)
  • Use logical direction utilities everywhere shared (ps-*, border-e, start-*)
  • Set all numbers tabular; add aria-label + title to icon-only buttons

Don't

  • Hardcode brand hex — tenants re-theme via parallel Foundations libraries (Dubai Sports, Healthx, Elitex…)
  • Reach for a Primitive directly in UI code when a Semantics token exists
  • Add shadows or hover lifts outside modals, the drawer, and auth
  • Put accent color in nav, menu highlights, or hovers — chrome stays Gray
  • Use physical direction utilities (pl-*, border-r) in shared components — RTL breaks
